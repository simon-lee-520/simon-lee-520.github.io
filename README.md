# Simon Blog

一个基于 `Hexo` 构建、使用 `Butterfly` 主题生成的个人静态博客站点仓库。

线上地址：<https://simon-lee-520.github.io/>

## 项目简介

本仓库采用**双分支维护方式**：

- `master` 分支：保存 Hexo 生成后的静态站点文件，用于 `GitHub Pages` 部署
- `hexo-source` 分支：保存博客源码，包括文章、主题配置、站点配置与构建环境

当前你看到的目录内容来自 `master` 分支，因此这里主要是已经生成好的页面、样式、脚本、图片和搜索索引文件。  
如果需要新增文章、修改主题配置、调整 Hexo 设置或重新构建站点，请切换到 `hexo-source` 分支进行维护。

这种分支划分方式适合：

- 将部署产物与站点源码分离
- 保持 `GitHub Pages` 发布分支结构简洁
- 降低源码配置与线上静态文件混杂带来的维护成本

## 分支说明

### `master`

用于部署的静态站点分支，主要包含：

- 已生成的 HTML 页面
- CSS / JavaScript / 图片 / 字体等静态资源
- `search.xml` 等搜索索引文件

一般情况下，不建议直接在该分支长期维护内容逻辑；除少量紧急修复外，推荐始终从 `hexo-source` 分支修改后重新生成并发布。

### `hexo-source`

用于日常开发和内容维护的源码分支，通常包含：

- Hexo 配置文件
- 文章源文件
- 主题配置
- 构建依赖
- 发布脚本

所有文章撰写、主题调整、插件配置、构建与部署操作，都应优先在这个分支完成。

## 技术栈

- 静态博客框架：`Hexo 8.1.1`
- 主题：`Butterfly 5.5.4`
- 部署方式：`GitHub Pages`
- 前端资源：HTML / CSS / JavaScript
- 第三方资源：
  - `Font Awesome`
  - `Pace.js`
  - `typed.js`
  - `APlayer`
  - `busuanzi`

## 当前站点特性

结合仓库中的页面和自定义脚本，当前站点具备以下能力：

- 首页、归档、标签、分类、关于页等静态页面
- 文章详情页展示
- 搜索索引文件 `search.xml`
- 亮色 / 暗色主题切换
- 页面加载进度条
- 首页副标题动态打字效果
- 随机背景图切换
- 自定义鼠标样式
- 页面标签动态标题提示
- 特定纪念日网站灰度显示
- 站点访问量统计

## 自定义内容说明

项目中有几处比较明确的个性化定制：

- `css/custom.css`
  - 页面头图与背景模糊渐入效果
  - APlayer 悬浮播放器展开交互
  - 自定义鼠标指针
  - 页脚和头图透明度调整

- `js/diytitle.js`
  - 用户切出页面后修改浏览器标签标题
  - 用户返回页面后恢复原标题并显示欢迎语

- `js/grayscale.js`
  - 在特定公共纪念日将整站切换为灰度样式

- `js/cursor.js`
  - 预留了动画光标相关逻辑，目前主要作为示例或待扩展脚本

## 本地预览

如果你当前位于 `master` 分支，可以直接把它当作纯静态站点进行本地预览，不需要额外构建。进入仓库根目录后，任选一种方式启动本地服务器：

### 方式一：使用 Python

```bash
python3 -m http.server 8080
```

然后在浏览器访问：

```text
http://localhost:8080
```

### 方式二：使用 Node.js 工具

如果你本地已安装 Node.js，也可以使用：

```bash
npx serve .
```

## 部署说明

本项目推荐的发布流程如下：

1. 切换到 `hexo-source` 分支
2. 编写或修改文章、主题配置和站点设置
3. 在 `hexo-source` 分支执行 Hexo 构建命令，生成静态文件
4. 将生成后的站点内容发布到 `master` 分支
5. 由 `GitHub Pages` 从 `master` 分支完成站点发布

如果仓库名为 `<username>.github.io`，通常会作为用户主页站点直接发布。

## GitHub Pages 配置

建议在仓库设置中将 `GitHub Pages` 的发布源指向：

- 分支：`master`
- 目录：`/ (root)`

这样每次 `master` 分支更新后，线上站点就会自动同步发布。

## 维护建议

- 日常内容更新、主题修改和配置调整，统一在 `hexo-source` 分支完成
- `master` 分支尽量只保存最终部署产物，避免手工修改后与源码分支脱节
- 如果需要临时修复线上样式或脚本，建议后续同步回 `hexo-source` 分支，保持两边一致
- 若后续增加自动化部署，可在 `hexo-source` 分支构建后自动推送到 `master`
